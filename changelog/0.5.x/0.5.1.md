# 0.5.1 — 2026-10-08

## Changed

- **Tool errors carry a request ID** — `data.requestId` is set and the error text closes with the request ID (mcp-ts-core 0.13.10).
- **The framework fills each tool's declared recovery hint** from its error contract (mcp-ts-core 0.13.10); the per-throw `ctx.recoveryFor(...)` forwards in the tool definitions are removed. Callers receive identical recovery text.
- **Server stack traces, request context, and `data.rootCause` no longer reach error data** (mcp-ts-core 0.13.7, 0.13.8, 0.13.13).
- **Tool input repair** — numeric and boolean strings, a lone string for a list field, and `null` at an optional key are repaired before validation (mcp-ts-core 0.13.14), as is an integer sent for a string field (0.13.9).
- **Docker image installs production dependencies in a `deps` stage on the build platform** and drops musl-only packages, so the multi-arch build runs no JavaScript under QEMU (mcp-ts-core 0.13.10, 0.13.11). Bun `1.4.0` → `1.4.2`.
- **`server.json` npm entries no longer pass `run`/`start:*` arguments**; the streamable-http entry sets `MCP_TRANSPORT_TYPE=http` (mcp-ts-core 0.13.11).
- **Framework skills, scripts, `CLAUDE.md`/`AGENTS.md`, `README.md`, `.env.example`, and ignore files** resynced to the 0.13.14 templates.
