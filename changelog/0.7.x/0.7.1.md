# 0.7.1 — 2026-10-29

## Added

- **`infoType`, `infoText`, `linkageTypes`** on each `ensembl_get_xrefs` entry — how Ensembl assigned the reference (`DIRECT`, `PROJECTION`, …), its source, and GO evidence codes (`IDA`, `IEA`), when Ensembl supplies them. Each `content[]` row shows the same values. (#59)

## Changed

- **`ensembl_gene_dossier`** step 5 calls `ensembl_get_homology` once each for `mus_musculus`, `rattus_norvegicus`, and `danio_rerio` and reports every row; step 6 takes the reviewed UniProt accession from the canonical transcript with `dbname="Uniprot/SWISSPROT"` and never requests a gene with `all_levels=true`; step 7 follow-ups are corrected. (#53, #54)
- **`ensembl_get_xrefs` description** drops the PubMed chain, adds `Uniprot/SWISSPROT` to the `dbname` examples, and labels each follow-up (UniProt, PubChem bioassays, OMIM, Reactome, PDB). (#54)
- **`ensembl_get_homology` `percId` and `percPos`** descriptions state they are measured over the target protein's length. (#54)
- **`ensembl-guide` skill 1.1** replaces the "query from the vertebrate side" advice with how to read the cross-division homology notice and the `target_not_compared` fallback. README and `docs/design.md` updated to match. (#55)

## Fixed

- **`ensembl_get_homology`** — a `target_species` outside the comparison Ensembl runs for the source species (a fly gene to `homo_sapiens`) failed with an unclassified GenomeDB error. It is now answered from Ensembl's pan-taxonomic comparison with a `notice`, or fails as the new declared `target_not_compared` reason. (#55)
- **`canonicalTranscript`** on `ensembl_lookup_gene` and `ensembl://gene/{id}` lost its trailing dot for transcripts without a version (`FBtr0084360.`), so `ensembl_get_sequence` accepts it. Versioned Ensembl IDs are unchanged. (#56)
- **`ensembl_get_xrefs`** `content[]` groups rows by database and display name, so GO and Projected GO rows sit under their own headings. (#57)
