# 0.7.2 — 2026-11-14

## Added

- **`strand`** on each `ensembl_predict_variant` record and colocated variant, on both output surfaces. A notice says to reverse-complement before matching alleles when a record's strand differs from a colocated variant's. ([#61](https://github.com/cyanheads/ensembl-mcp-server/issues/61))
- **`offset` and `nextOffset`** on `ensembl_query_region` and `ensembl_get_homology`. An offset at or past the end keeps `totalCount` and gets its own notice. ([#64](https://github.com/cyanheads/ensembl-mcp-server/issues/64))
- **`ENSEMBL_CLAMP_LIMITS`** (default `true`). `false` advertises `maximum: 5000` on `ensembl_query_region` `max_results` and rejects larger values instead of clamping them with a notice. Each clamp is logged and counted as `ensembl.count_input.clamped`. ([#64](https://github.com/cyanheads/ensembl-mcp-server/issues/64))

## Changed

- **`ensembl_query_region` `max_results: 0`** now returns a 5,000-row page with `nextOffset` instead of every row, and a value above 5,000 is clamped to 5,000 with a notice. ([#64](https://github.com/cyanheads/ensembl-mcp-server/issues/64))
- **`ensembl_query_region` rows** come in one fixed order: requested `feature` type, then `start`, `end`, `id`, `parentId`. ([#64](https://github.com/cyanheads/ensembl-mcp-server/issues/64))
- **Default `max_results`** is 25 on `ensembl_query_region` (was 100) and `ensembl_list_species` (was 50). `ensembl_gene_dossier` steps 3 and 5 and the `ensembl-guide` skill (1.2) describe paging and strand. ([#64](https://github.com/cyanheads/ensembl-mcp-server/issues/64))
- **`ensembl_get_homology` target symbols** are looked up five IDs per request, three requests at a time, within one ten-second budget, so a default page gets its names. Requests send `sequence=none`.
- **`ensembl://gene/{id}` and `ensembl://transcript/{id}`** ID descriptions cover species-form IDs (`AT1G01010`, `FBgn0000042`, `LRG_1`).
- **`@cyanheads/mcp-ts-core`** ^0.13.18 → ^0.13.22 with the resynced `framework-skills/`, `scripts/`, and `changelog/template.md`; `@biomejs/biome` ^2.6.3 → ^2.6.7; `@types/node` ^26.6.5 → ^26.6.6; `tsc-alias` ^1.9.9 → ^1.9.10; `vitest` ^5.0.5 → ^5.1.0; `engines.bun` >=1.4.0 → >=1.4.4.

## Fixed

- **`ensembl_predict_variant`** sent a `-1` region+allele to Ensembl as written, which scored the allele as a forward-strand base. The allele (each `/`-separated one, either case) is now reverse-complemented, `-` and structural-variant terms such as `DUP` pass unchanged, and a notice names the forward request sent. A `-1` allele equal to the forward reference fails `invalid_notation` naming that request. ([#66](https://github.com/cyanheads/ensembl-mcp-server/issues/66))
- **`ensembl_get_homology` and `ensembl_predict_variant` text output** rounded or padded `percId`, `percPos`, and SIFT/PolyPhen scores (`78.5714` shown as `78.6%`, `0` as `0.000`). `content[]` now renders the stored values. ([#65](https://github.com/cyanheads/ensembl-mcp-server/issues/65))
- **`ensembl_query_region`** applied `biotype` to variation and regulatory features without saying Ensembl ignores it for them. A notice now names those types as unfiltered, the empty-result and large-result notices cite `biotype` only for gene, transcript, and exon requests, and the large-result notice no longer suggests a biotype filter when `biotype` is set. ([#62](https://github.com/cyanheads/ensembl-mcp-server/issues/62))
- **`ensembl://transcript/{id}`** now refuses a gene, translation, or exon ID, and **`ensembl://gene/{id}`** a transcript, translation, or exon ID, with `wrong_object_type` naming the type found and where to read it. Both returned the wrong kind of record or an unclassified error. ([#63](https://github.com/cyanheads/ensembl-mcp-server/issues/63))
- **LRG versioned transcript and translation IDs** (`LRG_1t1.1`) resolve; the version is dropped before the request, as for `ENS…` IDs.
- **`ensembl_get_sequence`** numbers render en-US under any process locale.
- **`ensembl_predict_variant`** attributes a deletion's empty clinical-significance key to `-` when the colocated `alleleString` lists `-`.
- **`ensembl_get_xrefs`** empty-result notice names the `dbname` filter only when the request carried one.
