# 0.3.0 — 2026-07-03

## Added

- **`ensembl://species/{division}` resource** — division-addressable counterpart to `ensembl://species`, templated by `division` (`EnsemblVertebrates`, `EnsemblPlants`, `EnsemblFungi`, `EnsemblMetazoa`, `EnsemblProtists`). `list()` enumerates one addressable URI per division. ([#8](https://github.com/cyanheads/ensembl-mcp-server/issues/8))

## Changed

- **`ensembl_get_homology` symbol-mode `queryId` now returns the resolved Ensembl stable gene ID** — previously echoed the submitted symbol verbatim; now surfaces the stable ID from the upstream response's `data[].id` entry, falling back to the submitted symbol/ID only when the response carries no data entry. Gives callers a chainable ID instead of an opaque symbol. ([#6](https://github.com/cyanheads/ensembl-mcp-server/issues/6))
- **`ensembl://species` drops its `division` filter param** — the param was unreachable (a static URI has no template variable to populate it). The resource now always returns the endpoint default division (vertebrates on the default GRCh38 endpoint); read `ensembl://species/{division}` for a named division. ([#8](https://github.com/cyanheads/ensembl-mcp-server/issues/8))
- **`ensembl_list_species` description corrected** — no longer claims omitting `division` returns all divisions; states it returns the endpoint default division (vertebrates). ([#12](https://github.com/cyanheads/ensembl-mcp-server/issues/12))
- **`@cyanheads/mcp-ts-core`** `^0.10.9` → `^0.10.10`
