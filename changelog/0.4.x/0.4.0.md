# 0.4.0 — 2026-07-03

## Added

- **`ensembl_predict_variant` accepts dbSNP rsIDs** — third input format alongside HGVS and region+allele (e.g. `rs334`), routed to a new VEP `GET /vep/{species}/id/{id}` endpoint via the new `predictVariantId` service method. An rsID unknown to dbSNP surfaces as `not_found`; a malformed identifier as `invalid_notation`. ([#11](https://github.com/cyanheads/ensembl-mcp-server/issues/11))
- **`ensembl_query_region` exon features carry `parentId` and `rank`** — `parentId` (the `ENST…` parent transcript stable ID) and `rank` (1-based exon position within that transcript) explain why the same exon ID can appear on multiple rows: once per parent transcript it belongs to. ([#9](https://github.com/cyanheads/ensembl-mcp-server/issues/9))

## Changed

- **Chromosome-name guidance corrected** in `ensembl_query_region` and `ensembl_predict_variant` (descriptions, input schemas, error recovery text, and the empty-result notice) — no longer states chr-prefixed names are unsupported. Ensembl normalizes chromosome names; canonical vertebrate output omits the `chr` prefix, but a `chr`-prefixed name (e.g. `chr13`) is also accepted. ([#10](https://github.com/cyanheads/ensembl-mcp-server/issues/10))

## Fixed

- **`ensembl_gene_dossier` prompt's variant workflow corrected** — step 3 no longer claims `ensembl_query_region` can identify HIGH/MODERATE impact variants (query_region doesn't report functional impact); step 4 now attributes impact to VEP and offers a valid rsID example (`rs334`), consistent with the new rsID input support. ([#7](https://github.com/cyanheads/ensembl-mcp-server/issues/7))
