# 0.6.0 — 2026-10-13

## Added

- **`ensembl_list_species` paging** — `max_results` (default `50`, `0` uncapped) and `offset` in; `nextOffset`, `truncated`, `shown`, and `cap` out (#3).
- **`ensembl_lookup_gene` alias fallback** — a symbol `/lookup/symbol` misses resolves through `/xrefs/symbol`, reported as `matchedAlias`; patch and haplotype copies are set aside, and a failed reference-region read keeps every candidate; an alias lookup Ensembl never answers fails only that symbol, as `unavailable` (#20).
- **`ensembl_lookup_gene` batch items are typed** — `succeeded` and `failed`, each carrying `query`, plus `reason` and `recovery` on failures (#18).
- **Region grammar** `[species:]chr:start(-|..)end[:strand]` in `ensembl_get_sequence` and `ensembl_query_region`, with a `:1`/`:-1` strand suffix; a species prefix wins over `species` (#29, #31, #33, #36, #42).
- **`ensembl_query_region` `species` is optional** — a bare region without one fails as `missing_species` (#42).

## Changed

- **`ensembl_list_species` and the `ensembl://species` resources return 50 species by default** — pass `max_results: 0`, or page with `offset`, for the full list; the resources carry a paging notice. `openWorldHint` is now `true` (#3).
- **`ensembl_get_sequence` with an `ENSP…` ID and `genomic`, `cdna`, or `cds` fails as `type_mismatch`** instead of returning protein residues labelled as nucleotides (#30).
- **An ambiguous `symbol` returns `ambiguous` with its candidates and no `gene`** (#20).
- **A `symbols` batch on an unknown species throws `invalid_species`** instead of returning every item failed (#18).
- **Unrecognized Ensembl 400s are `ValidationError` (-32007)**, not `NotFound` (-32001) (#34).
- **Unknown species on `ensembl_predict_variant` and `ensembl_get_homology` raises `invalid_species`**; unknown-species recovery hints point to `ensembl_list_species` with `nameContains` (#37, #3).
- **Upstream timeouts** — 180 s per attempt within a 240 s per-tool-call deadline (#38).
- **Docker and `packageManager` pin Bun `1.4.2` → `1.4.3`**; framework skills, `CLAUDE.md`/`AGENTS.md` SDK version, and `README.md` resynced.

## Fixed

- **Ensembl database-outage and Perl-crash text no longer reaches callers**; outages, crashes, and response bodies that are not JSON surface as retryable unavailability, never as an input error (#34).
- **`ensembl_predict_variant` region+allele rejections carry a reason** — an allele matching the reference or outside A/C/G/T and SO terms is `invalid_notation`, an unknown sequence region `not_found` (#34).
- **`ensembl_get_sequence` reports an unknown region species as `invalid_species`** and a non-coding transcript asked for `protein` or `cds` as `type_mismatch`, each with its recovery (#29).
- **A trailing `.N` version on an `ENS…` stable ID is dropped** on lookup, sequence, xrefs, homology, and the gene and transcript resources; HGVS notation and non-`ENS` IDs are untouched (#41).
- **`ensembl_get_homology` with an unknown ID returns `not_found`** instead of an empty success (#40).
- **Region tools reject reversed ranges and malformed colon IDs before any request**; a species with a digit in its name no longer routes to stable-ID mode (#29, #31, #33).
- **`M` and `chrM` no longer resolve to an unrelated patch scaffold** — they are checked per species against Ensembl's synonym list and rejected only where Ensembl resolves them away from the mitochondrion (#39).
- **A species-prefixed `ensembl_query_region` region no longer fails with a strand error** (#42).
